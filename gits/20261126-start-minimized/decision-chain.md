# 打开只驻留托盘 · 决策链（decision-chain）

## D1 为什么改行为，而不是把面板做小

用户抱怨的是「打开时跳出来、挡住页面」这件事本身，不是面板的长宽。把面板缩小只是缓解遮挡，
「打开就抢占视线」的行为还在；而托盘应用的默认契约是「启动即静默驻留」。
所以改行为、不改尺寸——左键面板该多大还是多大，读得清比挡不住更重要。

备选：
- 面板缩小 / 压缩布局 —— 治标，且面板本来就是「要看时叫出来」的，缩小反伤可读性。否决。
- 启动时弹个托盘气泡 —— 气泡不是「菜单」，但仍是弹出物；用户要的是「安静」。否决。

## D2 为什么第二次双击也静默（推翻 README 里写过的行为）

「第二次双击把面板叫出来」当初是为了修「双击 exe 毫无反应」。但用户最自然的动作就是
**双击桌面 / 开始菜单图标**，所以这条路径恰好就是「打开的时候」的主要来源。
托盘图标已经在、也点得到，就不该再弹东西。不会变成死胡同：托盘图标本身就在。

## D3 为什么保留「托盘图标被关掉时，唤醒仍弹面板」

菜单里关掉托盘图标之后，exe 是唯一入口；这时弹面板是拿回菜单的唯一路径（面板上右键 = 菜单）。
去掉这一条，用户只能去改 `config.ini` 才能把菜单找回来——那才是真的死胡同。
判据用「托盘对象是否真的挂上了」（`st.tray.is_some()`），而不是配置项，因为 `add()` 可能失败。

## D4 为什么让 `--minimized` 与 `start_minimized` 真正生效，而不是删掉失效参数

两者都已经躺在用户机器上：自启项与 `tools/install.ps1` 一直传 `--minimized`，
`config.ini` 里一直写着 `start_minimized=1`，但一个没人解析、一个没人读。
留着当装饰是负债——它们会让人误以为「开机启动已经是静默的」，而实际行为取决于代码路径。
修成真开关之后，行为与配置名自解释。

优先级（从高到低）：`--panel`（调试/截图，显式要面板） > `--minimized`（强制静默） >
`[system] start_minimized`（默认 1=静默；0=启动就弹）。

## 待观察风险（诚实记录）

- **双击 exe 现在「没反应」**：这正是 v1.1.1 修过的观感问题，本次按用户要求回到静默。
  若再被反馈「双击没反应」，下一步是给托盘图标做一次短暂高亮/气泡（不动面板），而不是恢复弹面板。
- **`start_minimized=0` 是弹面板的唯一配置入口**，只在启动瞬间生效；改完要重启进程才看得出来。
  面板开着时改配置不会有任何即时反应（未做热读，v1 明确不做配置文件热加载）。

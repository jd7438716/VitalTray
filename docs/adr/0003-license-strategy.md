# ADR 0003：许可策略——上游多为 GPL，本项目为何保持 MIT

- 状态：已接受（Accepted）
- 日期：2026-11-26
- 相关：[licenses.md](../licenses.md) ｜ [ADR 0004 更名](0004-rename-to-vitaltray.md) ｜ [PLAN.md](../../PLAN.md) 第 2 节（洁净室）

## 背景

本项目的参考对象里，多数是 **GPL-2.0 / GPL-3.0**（上游 C++/Qt 项目与其 5 个派生仓库、Solaar、
OpenRazer、HeadsetControl），少数是 MIT / BSD / WTFPL / MPL-2.0，另有两个项目明确禁止参考。
而本项目以 **MIT** 发布。

问题：**"参考过 GPL 项目"本身会不会让 MIT 变成违约？** 需不需要改成 GPL？

## 决策

**保持 MIT**，并以"洁净室 + 可执行门禁 + 来源台账"三件套来承担举证责任。

## 依据

### 1. 版权只约束"表达"，不约束"事实"与"思想"

| 我们取了什么 | 属性 | 是否受版权保护 |
|---|---|---|
| VID/PID、usage page、帧格式、字节偏移、校验算法、时序 | 事实 | 否（*Feist v. Rural*：事实无版权） |
| 驱动表、轮询调度、托盘/菜单结构、插件分层 | 思想 / 方法 | 否（idea–expression 二分） |
| 具体函数体、结构体、注释、命名、文件组织 | 表达 | **是**——但本项目没有取 |

GPL 的义务绑定在「复制、修改、分发**衍生作品**」上。我们分发的是自己写的 Rust 二进制，
不是上游 C++ 代码的衍生作品，因此不触发 GPL。

### 2. 为互操作而独立重实现有判例支持

- *Sega v. Accolade*（9th Cir. 1992）：为兼容而反编译/阅读目标代码不构成侵权。
- *Google v. Oracle*（2021）：重实现 API 声明可属合理使用。
- 本项目更进一步：连"反编译"都不需要，上游源码是公开的，读它学协议事实更无争议。

### 3. 已实测"没有逐字复制"（不是口头保证）

2026-11-26 用一次性脚本做过对照（方法可复跑，见 `tools/check-cleanroom.ps1`）：

| 检查 | 对象 | 结果 |
|---|---|---|
| 注释/字符串逐字重合 | 上游 260 个 C++ 文件中 **7682 条**候选 vs 本项目 66 个 `.rs` | **0 条** |
| 标识符搬运 | 上游 845 个 camelCase 名 → 本项目代码 | 19 个命中，**全部是 Win32 ABI 强制名**（`hInstance`/`lpfnWndProc`/`lpszClassName`…）或通用词 |
| 转 snake_case 后再查 | 同上 845 个 | 仅 `send_feature_report`、`cable_charging` 两个通用名 |
| 上游源码入库 | `git ls-files research` | **0 条**（`research/` 整目录 gitignore） |
| 品牌/资源复用 | 图标、截图、文案 | 无复用（全部自产） |

## 边界（MIT 兜不住的地方，必须单独管）

1. **商标 / 名称**：著作权许可（MIT 与 GPL 都一样）**不授予商标权**。GPLv3 §7(e) 甚至明确允许
   许可方"不授予商标权"。所以"代码清白"不等于"名字可用"——这也是本次更名的直接原因（见 ADR 0004）。
2. **专利**：MIT 无明示专利许可（GPL-2.0 有默示），若某厂商协议受专利保护，MIT 帮不了你。
   对"用户态读电量/温度"这类工具，实际风险低，但**低不等于零**。
3. **事实的选择与编排**：单条协议事实无版权，但"整张设备支持清单/驱动表顺序"可能构成编辑著作权
   （欧盟另有数据库权）。因此**不照抄上游的整表**，只取用到的条目。
4. **洁净室的意义是"证据"，不是"豁免"**：法律标准是表达是否实质性相似，不是"我关过窗口"。
   语言不同（C++/Qt → Rust）会显著降低相似度，但这是**概率**不是**证明**。
5. **字体 / 字形**：字体文件是软件、受版权保护；字形设计在部分法域另有保护。本项目只按名字引用
   Windows 系统字体、不复制不分发（见 [licenses.md §6](../licenses.md#6-字体只引用系统字体不分发字体文件)）。
   一旦需要自带字体，必须换成 OFL / Apache-2.0 等可再分发许可并更新 notices——
   系统字体与商业字体都不能塞进安装包。

## 后果

- 可以光明正大地标 MIT，同时公开发布（本项目已在发 Releases）。
- 必须持续守纪律，否则一次复制就让 MIT 在该部分失效、并让 README 的洁净室声明变成虚假陈述：
  - `tools/check-cleanroom.ps1`：CI 扫源码中的 GPL/上游标识；本地有 `research/` 时做逐字重合比对。
  - `tools/check-fonts.ps1`：仓库里出现字体文件即失败——界面只用系统字体（`licenses.md` §6）。
  - `tools/gen-notices.ps1 -Check`：随二进制分发的第三方许可声明不许过期。
  - `.github/pull_request_template.md`：「未复制第三方代码」为必勾项。
  - `docs/licenses.md`：来源台账，逐条写"参考了什么 / 落在哪 / 有没有代码进入"。

## 替代方案（评估过但未采用）

| 方案 | 代价 | 结论 |
|---|---|---|
| 改为 GPL-3.0 | 放弃 MIT 的商业友好性；对未复制代码的项目属自我惩罚 | 不采用 |
| 双许可（MIT + 商业） | 本项目无商业授权实体，维护成本 > 收益 | 不采用 |
| 不写任何许可（All rights reserved） | 与"开源工具"定位冲突，且不能解决下游担忧 | 不采用 |
